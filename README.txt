CAROL FOR LANGUAGE COURSES
English / Arabic static website — six language courses

START HERE

1. Extract the ZIP into one folder.
2. Open index.html in a browser.
3. Use العربية / English to switch to the matching translated page.

All files are at the same level. The finished website uses ordinary HTML,
CSS and JavaScript, with no framework, database, installation or build step.
Course content and contact links work without JavaScript. An internet
connection is needed for Maps, WhatsApp, Instagram and other external links.

WHAT IS INCLUDED

- 20 public pages: home, course directory, six courses, about and contact,
  each in English and Arabic.
- German, English, Italian, Spanish, French and Turkish courses.
- The uploaded Carol logo throughout the site, matching icons and social image.
- Warm ivory, ink, terracotta and gold branding; responsive layouts and RTL.
- Mobile navigation, quick contact links and a WhatsApp draft composer.
- Course-specific enquiry links that select the matching language.
- Unique metadata, structured business/course data and crawlable navigation.
- An offline settings tool to generate the final canonical/hreflang URLs,
  sharing-image URLs and a multilingual sitemap once your URL is known.

These are courses to study. The website interface is in English and Arabic.
Spanish is included as spanish.html and spanish-ar.html.

GITHUB PAGES: PUBLISH FROM THE REPOSITORY ROOT

1. Create or open the repository you want to use.
2. Upload the EXTRACTED files to the root of the repository. index.html must
   be at that root, not inside another folder. Include the empty .nojekyll file.
3. Open the repository's Settings > Pages.
4. Under Build and deployment, select Deploy from a branch.
5. Choose the publishing branch (usually main), choose / (root), and Save.
6. Wait for GitHub to report your live HTTPS website address.
7. Complete the final-URL setup below and upload the resulting updated files.

Relative links/assets support a github.io user site, a repository project path
or a custom domain. A custom domain and DNS are configured separately in
GitHub Pages. No React, npm installation, PHP or server runtime is needed.

REQUIRED FOR COMPLETE SEO: ADD YOUR REAL PUBLIC WEBSITE URL

The final GitHub owner/repository or domain was not provided. The initial
sitemap is intentionally empty, and no public address has been guessed.
The website itself is ready to open now.

1. Open site-settings.html LOCALLY from the extracted folder in desktop
   Chrome or Edge.
2. Select that same complete website folder.
3. Paste the full HTTPS website address, without index.html. Include the
   repository folder for a GitHub project site.
4. Optionally add an existing business email and exact Facebook page URL.
5. Choose Download updated website.
6. Extract the new ZIP into a new folder and replace the repository files
   with those updated files.

This writes real absolute canonical URLs, reciprocal English/Arabic language
alternates, social-image URLs, organization/course/breadcrumb identifiers,
and a populated 20-page sitemap into the STATIC files. It also updates the
robots sitemap reference, manifest and llms.txt directory.

The settings tool works locally: it reads your chosen files and downloads a
new ZIP. It does not upload data, publish, change your original folder or
collect student enquiries. Only files listed in site-files.json are exported.
The owner tool is marked noindex and is not linked in the public navigation.

After publishing, verify the website in Google Search Console, submit the
full sitemap.xml URL, and add the website link to the correct Google Business
Profile and Instagram. Keep the name, address, phone and course list consistent.
A robots.txt under a GitHub repository subpath does not govern the origin
root; submit the sitemap directly and check origin-root restrictions separately.

WHATSAPP ENQUIRIES

Course buttons open a prepared WhatsApp draft. The visitor decides whether
to send it. The contact form composes a draft; it does not submit a registration
or send an email. No private account credentials are needed in the website.

OPTIONAL: EDITING THE SOURCE

business-profile.json — shared business information and final base URL
site-content.js       — course list, English copy and Arabic copy
build-site.mjs        — shared templates and general page wording
style.css             — branding, typography, responsive and Arabic styles
script.js             — mobile navigation and WhatsApp composer
site-engine.js        — metadata, structured data and discovery generation
site-settings.*       — local owner configuration and flat ZIP export

The optional generator uses Node.js 18+ with no packages. After changing the
source, run this command from the extracted folder:

  node build-site.mjs

Node is NOT used by the live website, and all HTML is already generated.
Language lists, course links, course pages, the contact selector and metadata
are derived from site-content.js. Add a complete course object with a unique
slug and both English/Arabic copy to add another course. Remove obsolete HTML
files explicitly when renaming or deleting a course and arrange redirects on
the host where possible. Direct HTML edits are overwritten by the generator.
Keep the CAROL comment markers so the local settings tool can update metadata.
