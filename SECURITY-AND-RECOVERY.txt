WHAT THE WEBSITE CANNOT PROTECT AGAINST

If someone obtains repository write access, they can replace the displayed
phone number, links, scripts or pages. HTML, a hidden URL, a browser password
prompt or a checksum stored in the same repository cannot prevent that.
Copying the public repository by itself gives no permission to modify yours.

PROTECT THE ACCOUNTS

1. Use different, unique passwords for GitHub, Namecheap and the email account
   used to recover them. Protect that email account with two-factor login too.
2. Enable two-factor authentication on GitHub and Namecheap. Add a GitHub
   passkey where supported. Save recovery codes outside the repository in a
   password manager or another safe offline location.
3. Keep GitHub collaborators and authorized applications limited to those you
   actually need. Review and remove unfamiliar sessions, keys or tokens.
4. Verify carollanguages.site in your GitHub PERSONAL account's Pages settings
   using the DNS TXT challenge. Keep the verification TXT record afterward.
   Verification protects against another GitHub account claiming an unlinked
   domain; it does not prevent defacement from a compromised authorized account.
5. Keep Namecheap ownership and recovery access independent of repository
   files. Do not create wildcard DNS records for this setup.
6. Save this trusted ZIP outside GitHub: on your computer plus an independent
   backup. Keep screenshots or a note of the expected DNS records separately.
7. Note the registration expiry and renewal setting. If registration expires,
   the domain may stop working and can eventually become available to others.

IF THE REPOSITORY OR ACCOUNT IS COMPROMISED

- Secure your recovery email and Namecheap account first and verify the DNS.
- Stop the malicious site being served: if GitHub access remains, disable its
  publishing while recovering it. If you cannot access GitHub, use Namecheap
  to repoint the domain to a clean host/maintenance page that you control.
- Recover GitHub, remove attacker access, revoke affected credentials and
  restore the trusted ZIP. Alternatively publish the backup from a clean,
  secured hosting account and reconnect the domain.
- Confirm the visible business identity, both telephone numbers, Maps,
  Instagram and WhatsApp destination against the original business records.
- Check the whole source for unexpected scripts before publishing it again.

Keeping control of Namecheap and an independent backup gives you a recovery
path. It is not a guarantee against account theft or website downtime.
